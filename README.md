# 빌딩스코프 — 3D 건물 시설관리 시제품

Vite와 Three.js로 제작한 한글 웹 프로그램입니다. 실제 도면이나 실시간 설비 연결을 사용하지 않는 가상 건물입니다.

## PC에서 실행하기

1. Node.js 22.12 이상(권장: Node.js 24 LTS)을 설치합니다.
2. 소스 ZIP을 받았다면 압축을 풀고, `package.json`이 있는 폴더에서 터미널을 엽니다.
3. 다음 명령을 순서대로 실행합니다.

```sh
npm ci
npm run dev
```

4. 터미널에 표시되는 로컬 주소를 PC의 Chrome 또는 Edge에서 엽니다. 기본 포트는 5173입니다. 포트가 사용 중이면 Vite가 표시하는 새 포트를 사용하세요.
5. 종료할 때는 터미널에서 Ctrl+C를 누릅니다.

`index.html`을 더블 클릭하는 방식으로는 실행되지 않습니다. WebGL을 지원하는 브라우저와 하드웨어 가속이 필요합니다. 설치할 때 npm 레지스트리 연결이 필요하며, 실행 중 외부 폰트나 3D 모델을 다운로드하지 않습니다.

## 사용법

- 왼쪽 버튼 드래그: 건물 회전
- 마우스 휠: 확대·축소
- 오른쪽 버튼 드래그: 화면 이동
- 층별 버튼: 선택한 층만 표시하고 시점 이동
- 전체 건물: 모든 층 표시
- 설비 모형·설비 이름·왼쪽 설비 목록 클릭: 해당 층 이동 및 이름/설치 위치 표시
- 시점 초기화: 현재 선택 층 또는 전체 건물의 기본 시점으로 복원
- 설비 이름 표시 버튼: 3D 설비 이름표 표시 전환

## 가상 건물 및 설비

지하 1층과 지상 1~5층, 반투명 외벽, 층별 슬래브, 가상 사무실/복도/로비로 구성됩니다. 지하층도 확인하기 쉽게 지면 아래를 가리지 않은 단면 개념으로 표현합니다.

| 종류 | 이름 | 설치 위치 |
| --- | --- | --- |
| 서버 | 방재실 서버 | 지하 1층 방재실 |
| CCTV | 출입구 CCTV | 지상 1층 주 출입구 |
| CCTV | 복도 CCTV | 지상 3층 중앙 복도 |

설비 데이터는 `src/main.js`의 `equipment` 배열에 있습니다. 실제 장비 상태, CCTV 영상, 도면 가져오기, 로그인 및 데이터 저장은 이번 시제품 범위에 포함되지 않습니다.

## 빌드

```sh
npm run build
npm run preview
```

빌드 결과는 `dist/`입니다. 정적 웹 호스팅에 배포할 수 있습니다. 공개 배포는 아직 수행하지 않았습니다.

## 검증 결과

- 프로덕션 빌드 및 JavaScript 구문 검사 통과
- 설치된 Chromium + Playwright에서 실제 WebGL 렌더링 확인
- 6개 층 표시, 층별 필터, 설비 3대의 상세 정보, 다른 층 선택 시 선택 해제 확인
- 설비 이름표 클릭·표시 전환, 회전, 확대·축소 입력, 시점 초기화 실행
- 390px 모바일 화면에서 가로 넘침 없음 확인
- 검증 중 브라우저 JavaScript 런타임 오류 없음

브라우저 검증은 이 클라우드의 Chromium 소프트웨어 렌더링으로 수행했습니다. 실제 PC의 GPU, 다른 브라우저 및 장시간 사용 성능은 별도 확인이 필요합니다.

## GitHub Pages 자동 배포

이 저장소 이름은 `-`이므로 Vite의 `base`는 `/-/`로 설정되어 있습니다. 저장소 이름이나 사용자 정의 도메인이 바뀌면 이 값도 수정해야 합니다.

`.github/workflows/deploy-pages.yml`은 `main`에 코드를 올리거나 수동 실행할 때 Node.js 24로 의존성을 설치하고 빌드한 `dist/`를 GitHub Pages에 배포합니다. 별도의 토큰이나 비밀 키를 등록할 필요가 없습니다.

최초 설정:

1. GitHub 저장소에서 **Settings → Pages**를 엽니다.
2. **Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
3. 저장소의 **Actions** 탭을 엽니다. 실행 허용 안내가 있으면 워크플로 실행을 허용합니다.
4. 왼쪽에서 **GitHub Pages 배포**를 선택합니다.
5. **Run workflow → Branch: main → Run workflow**를 누릅니다.
6. 실행 결과에서 빌드와 게시 작업이 모두 초록색인지 확인합니다. 환경 승인 대기가 표시되면 **Review deployments**에서 `github-pages` 배포를 승인합니다.
7. **Settings → Pages → Visit site** 또는 배포 결과에 표시된 주소를 엽니다.

기본 예상 주소는 `https://bellusnine.github.io/-/`입니다. 실제 주소는 성공한 배포 결과에서 확인하세요. 최초 Pages 설정 전 자동 실행된 작업은 실패할 수 있으므로 위 설정 후 수동 실행하세요. 이후에는 `main` 변경 시 자동 배포됩니다.

GitHub Pages로 게시하면 웹사이트와 빌드에 포함된 정보가 인터넷에 공개됩니다. 현재 데이터는 가상 설비 정보입니다. 실제 고객의 민감한 시설 정보나 비밀 키를 코드에 넣지 마세요. Pages 기능의 사용 가능 여부는 저장소 공개 범위 및 GitHub 요금제에 따라 다릅니다.
